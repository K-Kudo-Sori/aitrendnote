作業を止めずに進めるClaude Codeの/btw・/fork・/rewindなどの使い分け

Claude Codeで作業を止めずに進めるためのコマンドの使い分けを整理した記事。/btwは作業中でも横から質問でき、回答はメインの会話履歴に残らないので文脈を汚さない。/branchは会話を複製してその場で切り替え、/forkは複製した会話を別セッションとして裏で動かし、基本的にworktreeを作るので元の作業とファイルがぶつからない。そのほか/rewindで変更を巻き戻す方法や、起動時に --fork-session で会話を複製するTipsも紹介している。

Claude Code の /ship を図解する

Claude Codeにベータ版として加わったスキル「/ship」の流れを、実行ファイルに組み込まれたプロンプトを読んで図解した記事。/shipは、コミットとpush、PRの作成、レビューと修正、マージかクローズまでの見張りを1つのセッションで受け持ち、最長7日間PRを監視する。PRの状態を2分ごとに確かめるのはClaude Codeの本体で、変化があったときだけClaudeを起こすので、/loopと違って静かなPRなら使用量はほとんど増えない。読むコメントの発信元を限定したり、同じ原因でのpushを3回までにしたりする安全策があり、最後のマージは人が行う設計になっている。

プレイングマネージャーから抜け出せない人が見落としている3つの視点 ― 権力を「大きく」し、腐らせないために【権力シリーズC】

部長以上を目指す30〜40代のエンジニアやリーダーに向けた、「権力」シリーズのC。必要なのは専門性をさらに深めることより視点を増やすことだとし、プレイングマネージャーから抜け出すための3つの視点を挙げている。失敗を部下ではなく仕組みの責任として捉えること、部下を信頼して任せること、優秀な部下の成長を組織に必要なものとして受け入れることである。また、権力は大きくなるほど腐りやすく、良い権力の基準は「組織のために発揮できているか」の1つだけだと述べ、各項目にセルフチェックを用意している。

書籍『やっぱり権力』をもとに、AI時代に人間に残る価値を論じる「権力」シリーズの総論。ここでいう権力とは偉そうに振る舞う力ではなく、方向性を決めてその責任を取るポジションのことだと定義している。AIは知識量では人間に勝てても、平気で嘘をつき、結果に責任を取ってはくれないため、「AIは参謀にはなれても王にはなれない」と説く。静かな退職を選ぶことは生殺与奪権を他人に握らせることだと指摘し、キャリア段階別のA/B/Cの記事へ案内している。
